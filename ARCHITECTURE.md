# Архитектура fuchs-image-optimizer

После однократной установки через `npm ci` пользователь запускает `npm start`. В браузере открывается локальная страница. Пользователь выбирает одно или несколько изображений, видит миниатюры исходников, задаёт общий выходной формат и степень сжатия и одной кнопкой запускает обработку всех выбранных файлов. Для каждого изображения страница показывает размеры до и после обработки и ссылку для скачивания результата. После установки приложение работает офлайн.

## Пакетное сжатие и миниатюры

Браузер принимает файлы через поле с атрибутом `multiple`. Сразу после выбора он показывает список в порядке выбора. Рядом с именем каждого файла выводится уменьшенное изображение самого исходника с сохранением пропорций. Миниатюра загружается локально из `File` через объектный URL. Если браузер не смог показать изображение, строка сохраняет имя файла и сообщает, что предпросмотр недоступен.

По нажатию кнопки браузер фиксирует настройки для всей партии и последовательно отправляет файлы в `POST /api/optimize`. Каждый запрос использует один серверный слот. У каждой строки свои состояние, ошибка или результат. Сбой одного файла позволяет продолжить обработку остальных и скачать уже готовые изображения. При замене списка или уходе со страницы браузер освобождает объектные URL миниатюр и результатов.

### Предпросмотр результата и скачивание

В карточке каждого файла при любой ширине экрана области расположены вертикально. «Исходник» находится сверху, «После сжатия» — непосредственно под ним. До готовности нижняя область показывает состояние обработки. При успехе она отображает миниатюру из объектного URL полученного `Blob` с сохранением пропорций, размер результата и ссылку «Скачать». При сбое в нижней области остаётся сообщение об ошибке. На узком экране карточка помещается по ширине экрана без горизонтальной прокрутки.

После завершения партии кнопка «Скачать все» сохраняет успешно обработанные изображения одним ZIP-архивом. Кнопка доступна при наличии хотя бы одного результата. Браузер формирует архив локально из тех же файлов, которые доступны по отдельным ссылкам. При совпадении имён добавляет числовые суффиксы, чтобы каждый файл попал в архив. Повторная обработка и замена партии сбрасывают прежние результаты и ссылки на архив.

## Границы и стек

| Компонент | Решение и основание |
| --- | --- |
| Локальный сервер | Node.js 24 LTS, ES-модули и встроенный `node:http`. Три статических ресурса и один API-метод умещаются в явную таблицу маршрутов. [Цикл поддержки Node.js](https://nodejs.org/en/about/previous-releases) |
| Страница | HTML с нативными элементами формы, CSS и JavaScript. Браузер отправляет `File` через `fetch` и получает `Blob`. Сборка клиента и загрузка ресурсов из интернета не требуются. |
| Кодек | `sharp` (libvips) читает и записывает JPEG, PNG и WebP через единый API. Выбрать совместимый с Node.js 24 релиз и зафиксировать зависимости в lock-файле. [Установка](https://sharp.pixelplumbing.com/install/) · [Параметры кодеков](https://sharp.pixelplumbing.com/api-output/) |
| Изоляция | На запрос сервер запускает один дочерний Node.js-процесс через `node:child_process`. Для локальной интерактивной работы приемлема задержка запуска. Зато сервер может остановить зависший нативный декодер и обслужить следующий файл. |
| Открытие страницы | Пакет `open` передаёт URL браузеру по умолчанию в Windows, macOS и Linux. Сервер передаёт только адрес, сформированный после запуска. [Документация open](https://github.com/sindresorhus/open) |
| Проверки | ESLint, TypeScript для статической проверки JS с JSDoc, `@types/node` для выбранной ветки Node.js, встроенные `node:test` и `node:assert/strict`. |

## Запуск и состояние

`main.js` слушает `127.0.0.1` на порту `0` (свободный порт выбирает ОС). После события `listening` выводит полный URL и один раз открывает его. При недоступном браузере сервер продолжает работать, URL можно открыть вручную. Импорт фабрики из `server.js` не открывает сокеты или окна. При остановке приложения завершается и активный дочерний процесс.

Состояние сервера — один слот на экземпляр сервера, общий для всех вкладок. Маршрут занимает его до чтения тела. Одновременно выполняется один запрос, очередь ожидания имеет длину ноль. Пока слот занят, другой запрос сразу получает `429 BUSY`. База данных, таблицы заданий и файлы на диске для этого сценария не нужны. Вход и результат находятся в памяти в пределах одного запроса. Запись скачанного файла выполняет браузер по выбору пользователя.

## HTTP-контракт

| Запрос | Ответ |
| --- | --- |
| `GET /`, `GET /app.js`, `GET /styles.css` | `200`, соответствующий локальный ресурс с MIME-типом HTML, JavaScript или CSS. Сервер выбирает файл из фиксированной таблицы. |
| `POST /api/optimize?format=webp&quality=80` | Тело запроса содержит исходные байты одного файла. Обязателен `Content-Type: application/octet-stream`. Успех — `200` и байты изображения. |

Для любого запроса проверять `Host` по фактическому адресу и порту сервера. Для POST проверять совпадение `Origin` с локальным origin, если заголовок присутствует. Запрос без `Origin` допустим для локального CLI. Страница и API используют один origin.

| Параметр | Допустимые значения | Как применить |
| --- | --- | --- |
| `format` | Обязателен, ровно одно из `jpeg`, `png`, `webp` | Выходной формат. В форме изначально выбран WebP. |
| `quality` | Только для JPEG/WebP, целое 1–100, по умолчанию 80 | Качество кодирования с потерями. |
| `compressionLevel` | Только для PNG, целое 0–9, по умолчанию 6 | Уровень сжатия PNG без палитровой квантизации. |

Числовые параметры принимаются десятичными цифрами. Пустые значения, неизвестные или повторяющиеся ключи и параметры другого кодека дают `400 INVALID_OPTIONS`. Успешный ответ содержит `Content-Type` выбранного изображения, `Content-Length` результата и `Cache-Control: no-store`. Имя входного файла остаётся в браузере. Он предлагает для скачивания имя вида `photo-optimized.webp`, для JPEG использует расширение `.jpg`.

Для ошибок API тело имеет тип `application/json` и вид `{"error":{"code":"INVALID_IMAGE","message":"Не удалось прочитать изображение."}}`. Поле `code` стабильно, `message` предназначено для пользователя. После разрыва соединения отправлять ответ уже некому.

| HTTP | Код | Когда возвращать |
| --- | --- | --- |
| 400 | `EMPTY_INPUT`, `INVALID_OPTIONS` | Пустое тело или неверные параметры |
| 403 | `FORBIDDEN_ORIGIN` | Чужой Host или Origin |
| 404 / 405 | `NOT_FOUND` / `METHOD_NOT_ALLOWED` | Неизвестный путь / неверный метод известного пути (с заголовком `Allow`) |
| 408 | `UPLOAD_TIMEOUT` | Истёк срок приёма тела |
| 413 | `INPUT_TOO_LARGE`, `PIXEL_LIMIT`, `OUTPUT_TOO_LARGE` | Превышен соответствующий лимит байтов или пикселей |
| 415 | `UNSUPPORTED_MEDIA_TYPE`, `UNSUPPORTED_FORMAT` | Неверный Content-Type либо формат за пределами поддержки, включая анимацию |
| 422 | `INVALID_IMAGE` | Сигнатура допустима, но заголовок, кадр или пиксельные данные повреждены |
| 429 | `BUSY` | Другой запрос уже занял слот |
| 503 | `PROCESSING_TIMEOUT` | Истёк срок работы дочернего процесса |
| 500 | `INTERNAL_ERROR` | Сбой запуска, непредвиденное завершение процесса или ошибка сервера |

## Путь изображения и лимиты

1. **Браузер.** Для всех форматов форма показывает один ползунок «Качество» от 0 до 100 с шагом 1 и видимым текущим значением (изначально 80). При смене формата значение сохраняется. Для значения `q` клиент передаёт JPEG/WebP параметр `quality = Math.max(1, q)`, а PNG — `compressionLevel = Math.round(9 * (100 - q) / 100)`. Подсказка для PNG поясняет, что сжатие всегда без потерь, а меньшее значение ползунка задаёт более интенсивное сжатие. По отправке она блокирует повторное нажатие и отправляет исходный `File` без Base64. Фильтр выбора файла помогает пользователю, окончательную проверку выполняет сервер.
2. **Приём.** После проверки маршрута, origin, параметров и типа тела сервер резервирует слот. Лимит на вход — 16 МиБ (1 МиБ = 1 048 576 байт). Проверять объявленный `Content-Length` и считать реальные байты по мере чтения, в том числе для chunked-запросов. Прекращать накопление сразу при превышении. На приём тела отведено 30 секунд с момента резервирования слота. При досрочном отказе закрывать соединение после отправки ошибки, если осталось непрочитанное тело.
3. **Изоляция.** Родитель запускает `worker.js` текущим исполняемым файлом Node.js и передаёт проверенные настройки аргументами без shell. В stdin пишет исходные байты и закрывает поток. В stdout разрешены только байты результата. При ожидаемой ошибке worker завершается с кодом 1 и передаёт один код из таблицы в stderr. Родитель ограничивает чтение stderr, сверяет код со списком и трактует неизвестный сбой как `INTERNAL_ERROR`.
4. **Декодирование.** До передачи в декодер проверить сигнатуру JPEG, PNG или WebP. Лимит — 24 000 000 пикселей на изображение. Задать его в `limitInputPixels`, проверять размеры из метаданных и отклонять повреждения при полном декодировании. Поддерживается один кадр. Отклонять APNG по блоку `acTL` и анимированный WebP по признаку анимации контейнера либо метаданным страниц. Блоки читать с проверкой границ. [Параметры чтения sharp](https://sharp.pixelplumbing.com/api-constructor/)
5. **Кодирование.** Применить ориентацию EXIF, сохранить визуальные размеры и удалить исходные метаданные. Альфа-канал сохраняется для PNG/WebP, для JPEG прозрачность сводится на белый фон. Писать закодированный результат в stdout потоком. Родитель накапливает максимум 32 МиБ, при превышении останавливает worker. Отправить `200` только после успешного завершения и получения целого результата.
6. **Освобождение.** Срок обработки — 30 секунд с момента запуска worker, включая чтение метаданных и выдачу байтов родителю. При истечении срока или отключении клиента завершить процесс принудительно. Очистить таймеры, подписки и буферы на всех путях. Вернуть слот после закрытия процесса и завершения либо закрытия HTTP-ответа. Тесты могут подменять лимиты меньшими значениями.
7. **Результат.** Страница сравнивает `File.size` и `Blob.size`. Если файл вырос, показывает увеличение и оставляет скачивание доступным. При ошибке сохраняет файл и настройки для повтора. При замене результата или уходе со страницы освобождает предыдущий объектный URL. Элементы состояния сообщают пользователю об обработке, успехе и причине отказа.
