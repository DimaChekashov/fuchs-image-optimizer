# План реализации fuchs-image-optimizer

Выполняй спринты по порядку, по одному за раз. Для каждого спринта список файлов ниже включает реализацию и её проверки. Общая завершающая правка каждого шага — отметка в этом файле. Перед отметкой выполни критерий готовности и все три команды из [AGENTS.md](AGENTS.md) — `npm run lint`, `npm run typecheck`, `npm test`. Контракты, ограничения и назначение модулей заданы в [ARCHITECTURE.md](ARCHITECTURE.md).

## Спринт 1. Настройки сжатия и проверки проекта

- [x] **Цель.** Получить проверяемый JS-проект и чистую функцию разбора параметров, которую позже вызовет HTTP-маршрут.
- **Создать** `.gitignore`, `package.json`, `package-lock.json`, `eslint.config.js`, `tsconfig.json`, `src/options.js`, `src/errors.js`, `src/limits.js`, `test/options.test.js`.
- **Работа.** Настроить ES-модули, Node.js 24 и три команды проверки. Описать коды ошибок и числовые лимиты. Разбирать параметры из `URLSearchParams` с сохранением информации о повторах. Проверка типов должна охватывать JS в `src/`, `public/`, `test/` и конфигурацию ESLint по мере их появления.
- **Готово, когда** после `npm ci` проходят три команды. Тесты разбирают все три формата, подставляют значения по умолчанию, принимают граничные значения и отклоняют пропущенный формат, чужой параметр кодека, дубликат, дробь и выход за диапазон.

## Спринт 2. Локальный запуск и открытие страницы

- [x] **Цель.** Пользователь одной командой открывает страницу запущенного экземпляра.
- **Создать** `src/main.js`, `src/server.js`, `public/index.html`, `test/server.test.js`. **Изменить** `package.json`, `package-lock.json`.
- **Работа.** Добавить `open` и `npm start`. Реализовать фабрику HTTP-сервера и маршрут `GET /` для начальной HTML-страницы. Настроить привязку к loopback, проверку Host, обработку неизвестного пути и неверного метода. Открывать браузер только из точки входа.
- **Готово, когда** `npm start` выводит рабочий URL и открывает страницу. При недоступном обработчике URL приложение остаётся доступным по напечатанному адресу. HTTP-тесты на свободном порту проверяют HTML, 403, 404 и 405 с `Allow`, завершаются с закрытым сервером и без запуска браузера.

## Спринт 3. Преобразование одного изображения

- [x] **Цель.** Превращать входные байты и проверенные настройки в изображение выбранного формата независимо от HTTP.
- **Создать** `src/codec.js`, `test/codec.test.js`. **Изменить** `package.json`, `package-lock.json`.
- **Работа.** Подключить `sharp`. Реализовать проверку контейнера, числа кадров и размеров, ориентацию, работу с прозрачностью и потоковую выдачу. Тестовые изображения создавать в памяти, короткие повреждённые образцы формировать в самом тесте.
- **Готово, когда** тесты повторно открывают результат для JPEG, PNG и WebP и проверяют формат и визуальные размеры. Отдельные случаи проверяют альфа-канал, белый фон JPEG с допуском на потери, ориентацию EXIF, чужую сигнатуру, усечённый файл, анимированные PNG/WebP и превышение лимита пикселей.

## Спринт 4. Дочерний процесс и отмена

- [x] **Цель.** Ограничить время и объём вывода одного преобразования независимо от поведения кодека.
- **Создать** `src/worker.js`, `src/run-worker.js`, `test/run-worker.test.js`, `test/helpers/worker-double.js`.
- **Работа.** Связать кодек с бинарными потоками дочернего процесса. В родителе принять данные, параметры и `AbortSignal`, ограничить stdout/stderr, различать таймаут, отмену, ошибку изображения и неизвестный сбой. Обрабатывать закрытие потоков и процесса в любом порядке.
- **Готово, когда** реальный дочерний процесс возвращает декодируемый результат и передаёт ожидаемую ошибку повреждённого изображения. С тестовым процессом воспроизводятся зависание, переполнение stdout, отмена и аварийный выход. После каждого случая процесс закрыт, частичный результат отброшен и следующий вызов проходит.

## Спринт 5. HTTP-метод оптимизации

- [x] **Цель.** Провести изображение от локального HTTP-клиента до кодека и вернуть пригодный для скачивания ответ.
- **Создать** `src/optimize-route.js`, `test/optimize.test.js`. **Изменить** `src/server.js`, `src/main.js`.
- **Работа.** Подключить метод POST и проверку Origin, ограничить приём тела по времени и размеру, реализовать один слот для всех вкладок и сопоставление ошибок с HTTP. Связать отключение клиента и остановку приложения с отменой активной работы.
- **Готово, когда** интеграционный тест отправляет реальные байты в `POST /api/optimize?format=webp&quality=80`, получает `200 image/webp` и декодирует ответ. Тесты проверяют JSON ошибок, включая пустое тело, неверные настройки, тип тела, чужой Origin, битое изображение, превышение размера с `Content-Length` и без него. На уменьшенных лимитах воспроизводятся 408 и 503. Параллельный запрос получает 429. После таймаута или обрыва загрузки/обработки следующий запрос проходит.

## Спринт 6. Рабочая форма и приёмка запуска

- [ ] **Цель.** Пользователь выбирает изображение и настройки, оценивает размер результата и сохраняет файл.
- **Создать** `public/app.js`, `public/styles.css`. **Изменить** `public/index.html`, `src/server.js`, `test/server.test.js`, `README.md`.
- **Работа.** Завершить форму и маршруты статических ресурсов с корректными MIME-типами. Подключить POST, состояния обработки, сравнение размеров, скачивание и освобождение объектных URL. В README описать Node.js 24, `npm ci`, `npm start`, открытие по напечатанному адресу, форматы, лимиты и остановку через Ctrl+C.
- **Готово, когда** после `npm ci` и `npm start` пользователь в открывшейся странице обрабатывает один файл с двумя настройками, видит размеры до и после и открывает скачанный файл нужного формата. Проверить смену JPEG/WebP на PNG, доступность формы с клавиатуры, сообщение при увеличении размера, ошибку повреждённого файла и повторную отправку. После установки сценарий проходит с отключённым интернетом. HTTP-тесты подтверждают доступность JS и CSS.
