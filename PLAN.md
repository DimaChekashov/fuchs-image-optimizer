# План реализации fuchs-image-optimizer

Выполняй спринты по порядку, по одному за раз. Для каждого спринта список файлов ниже включает реализацию и её проверки. Общая завершающая правка каждого шага — отметка в этом файле. Перед отметкой выполни критерий готовности и все три команды из [AGENTS.md](AGENTS.md) — `npm run lint`, `npm run typecheck`, `npm test`. Контракты, ограничения и назначение модулей заданы в [ARCHITECTURE.md](ARCHITECTURE.md).

- **Готово, когда** после `npm ci` проходят три команды. Тесты разбирают все три формата, подставляют значения по умолчанию, принимают граничные значения и отклоняют пропущенный формат, чужой параметр кодека, дубликат, дробь и выход за диапазон.

## Спринт 5. HTTP-метод оптимизации

- [x] **Цель.** Провести изображение от локального HTTP-клиента до кодека и вернуть пригодный для скачивания ответ.
- **Создать** `src/optimize-route.js`, `test/optimize.test.js`. **Изменить** `src/server.js`, `src/main.js`.
- **Работа.** Подключить метод POST и проверку Origin, ограничить приём тела по времени и размеру, реализовать один слот для всех вкладок и сопоставление ошибок с HTTP. Связать отключение клиента и остановку приложения с отменой активной работы.
- **Готово, когда** интеграционный тест отправляет реальные байты в `POST /api/optimize?format=webp&quality=80`, получает `200 image/webp` и декодирует ответ. Тесты проверяют JSON ошибок, включая пустое тело, неверные настройки, тип тела, чужой Origin, битое изображение, превышение размера с `Content-Length` и без него. На уменьшенных лимитах воспроизводятся 408 и 503. Параллельный запрос получает 429. После таймаута или обрыва загрузки/обработки следующий запрос проходит.

Проверка спринта 9 выполнена. ESLint и проверка типов прошли, все 24 теста прошли.
